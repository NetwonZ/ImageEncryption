# 差分攻击评估异常：原因与修复报告

## 结论

`differential_analysis.py` 中的 NPCR/UACI 计算正确：在转为 `float64` 后计算绝对差，避免了 `uint8` 下溢；单像素明文修改也符合标准差分攻击实验。低 UACI 的根因在原加密扩散结构，不在评价指标。

## 原因

原始实现严格采用论文公开公式(5)：

```text
C[k] = (C[k] + C[k-1] + d[k]) mod 256
```

它是单向、线性的模加链。设某个螺旋位置的局部 XOR 输出发生差分 `Δ`，则后续位置的密文差分仍为相同的 `Δ (mod 256)`；该点之前完全不受影响。因此：

1. NPCR 取决于被修改像素在置乱后处于螺旋路径的哪个位置；
2. UACI 取决于一个很小且几乎恒定的数值差，而不是均匀随机的 0–255 差；
3. 在固定密钥下，公开公式(5)不可能稳定产生表10所示的 UACI ≈ 33.46%。

对 `output/demo/img3.png`（512×512，修改坐标 `(86, 358)`）的原始模式复现实测为：NPCR `94.9806%`、UACI `0.7327%`。这正符合上述线性链行为。

## 修复方案

新增可逆的 `hardened` 扩散模式，保留原 `paper` 模式用于逐公式核对。增强模式在局部 XOR 后执行以下两阶段：

```text
F[k] = (A[k] + SBox[F[k-1]] + d[k]) mod 256       # 螺旋正向
C[k] = (F[k] + SBox[C[k+1]] + d[k]) mod 256       # 螺旋反向
```

S-box 是置换，因此不同反馈状态不会在线性加法中合并；前向和反向链使任何螺旋位置的差异都能覆盖全图。两式均可直接逆解，已加入单元测试验证。

注意：这是一项为满足抗差分目标而加入的工程增强，**不是**论文公开公式(5)本身。论文表10若在固定密钥条件下确实达到理想值，则原文还应存在未公开的非线性反馈、明文敏感密钥派生或其他实现细节。

## 修复后实测

在相同的 `img3.png`（512×512）、相同的单像素修改坐标 `(86, 358)` 与相同混沌参数下：

| 模式 | NPCR | UACI | 可逆性 |
| --- | ---: | ---: | --- |
| `paper`（原始单向线性公式） | 94.9806% | 0.7327% | 通过 |
| `hardened`（双向非线性反馈） | 99.6338% | 33.4663% | 通过，逐像素完全恢复 |
| 理想参考值 | 99.6094% | 33.4635% | - |

同时执行 `python -m unittest discover -s tests -v`，5 项测试全部通过：混沌序列确定性、单轮置乱可逆、两种扩散模式可逆、完整加密解密可逆，以及增强模式的雪崩效应。

## 验证标准

运行：

```powershell
python -m unittest discover -s tests -v
python -m papers.adaptive_scrambling.differential_analysis
```

`hardened` 模式目标为 NPCR 接近 `99.6094%`、UACI 接近 `33.4635%`；`paper` 模式会保留低 UACI 行为，以便对照和审计。
